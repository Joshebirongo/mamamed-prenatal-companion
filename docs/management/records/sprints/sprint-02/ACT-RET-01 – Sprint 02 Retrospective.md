## 5. What Can We Improve?

| ID | Improvement Opportunity | Expected Benefit | Priority |
|---|---|---|---|
| MEJ-001 | Set clear priorities and break large tasks into smaller activities. | More realistic estimates and better time management. | High |
| MEJ-002 | Follow the GitHub task board and complete one feature or task at a time. | Better task organization and progress tracking. | High |
| MEJ-003 | Test each feature early and review code regularly. | Better code quality and earlier detection of problems. | High |
| MEJ-004 | Strengthen knowledge of React, Node.js, PostgreSQL, and testing. | Improved technical skills and confidence during implementation. | Medium |
| MEJ-005 | Identify blockers early and request instructor support quickly. | Fewer delays and faster problem resolution. | High |
| MEJ-006 | Allocate more time for revisions and track progress daily. | More realistic planning and fewer unfinished tasks. | High |

**Discussion Questions:**

- **How can we improve our sprint planning?** Set clear priorities, divide large tasks into smaller activities, and estimate them more carefully.
- **What could make our development process more efficient?** Following the task board and focusing on completing one feature at a time.
- **How can we improve code quality and testing?** Test each feature early and review the code regularly.
- **What technical knowledge should the team strengthen?** React, Node.js, PostgreSQL, and software testing.
- **How can we reduce blockers and unnecessary delays?** Identify difficulties early and ask the instructor for help quickly.
- **What should we change in the next sprint?** Plan more time for revisions and track progress daily.
